# КЛИК | Медиа-маркет — v9

Добавлено фото профиля для блогеров и контент-креаторов.

- фото запрашивается сразу после имени;
- сохраняется Telegram `file_id` в PostgreSQL;
- новые деплои фото не стирают;
- при повторном редактировании профиля фото можно заменить;
- фото показывается в карточке профиля, медиа-базе и при новом отклике бизнесу;
- старые профили без фото продолжают работать;
- остальная логика v8 не менялась.

Railway Variables без изменений:
BOT_TOKEN
ADMIN_ID
DATABASE_URL

## v16 — модерация регистраций
В «🛡 Модерация» добавлены три отдельные очереди:
- Заявки бизнесов
- Заявки блогеров
- Заявки контент-креаторов

Каждая анкета открывается по одной.
Кнопки:
- ✅ Принять
- ❌ Отклонить

После решения автоматически показывается следующая анкета из той же очереди.

Показывается счётчик:
«Осталось: N».

Новые регистрации получают статус pending.
После одобрения — active.
После отклонения — rejected.

Пользователь получает уведомление о результате модерации.


## v17 — сообщения / поддержка
Пользователь может написать в поддержку ТОЛЬКО через кнопку «Задать вопрос».

Сценарий:
1. Пользователь нажимает «Задать вопрос».
2. Бот просит написать вопрос одним сообщением.
3. Только следующее сообщение сохраняется как обращение.
4. Обычные сообщения вне этого сценария администратору не пересылаются.

В панели владельца:
- 💬 Сообщения
- Новые
- Закрытые

Карточка обращения показывает:
- роль
- текст вопроса

Действия:
- Ответить
- Закрыть

Ответ администратора отправляется пользователю в бот как «Ответ команды КЛИК».
Вся история обращений и ответов хранится в PostgreSQL и не стирается после deploy.


## v18 — обновление пользовательского меню
Добавлен единый механизм выдачи актуального меню по роли.

- /menu обновляет закреплённое меню без повторной регистрации.
- После завершения пользовательских сценариев бот может повторно выдать актуальную клавиатуру.
- После отправки вопроса в поддержку меню обновляется автоматически.
- /start по-прежнему работает, но больше не является единственным способом получить новое меню.

Важно: Telegram не позволяет молча заменить уже показанную Reply Keyboard без нового сообщения от бота. Поэтому актуальная клавиатура применяется при следующем предусмотренном взаимодействии/сообщении.


## v19 — умные уведомления о новых проектах
После одобрения проекта модератором бот автоматически уведомляет подходящих творцов.

Логика:
- заявка «Блогер» → только активным блогерам;
- заявка «Контент-креатор» → только активным контент-креаторам;
- онлайн / удалённый проект → география не ограничивает уведомление;
- оффлайн → уведомление получают творцы нужного города/региона;
- также уведомление получают творцы, указавшие готовность к выезду.

В уведомлении есть кнопка «Посмотреть проект».
Геофильтр влияет только на push-уведомление: сам проект остаётся доступным в каталоге согласно основной логике бота.


## v20 — напоминания бизнесу и итоги проекта

### Вечерний дайджест откликов
Каждый день в 20:00 по Москве бот проверяет новые отклики бизнеса.
Если после прошлого дайджеста появились новые отклики, бизнес получает одно сводное сообщение:
- общее количество новых откликов;
- сколько новых откликов по каждому проекту;
- кнопка «Посмотреть отклики».

Если новых откликов нет — сообщение не отправляется.

Час можно изменить через Railway Variable:
BUSINESS_DIGEST_HOUR
По умолчанию: 20.

### Завершение проекта
В разделе «Мои заявки» у активного проекта появляется кнопка «Завершить проект».

После завершения бот показывает карточку итогов:
- всего откликов;
- принято;
- отклонено;
- осталось без решения;
- выбранные творцы.

У завершённого проекта доступна кнопка «Итоги проекта».
